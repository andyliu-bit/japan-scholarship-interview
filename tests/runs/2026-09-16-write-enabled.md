## 2. 剥离与 diff（检查点 16）

### 第一次尝试：朴素剥离，**失败**

```
$ sed 's/[ ]*<!-- claims: C-[0-9]* -->//g' script-7min.md > script-7min.clean.md
$ diff script-7min.md script-7min.clean.md | grep -c "^[<>]"
2        ← diff 只出现标记行，按原规则「通过」
```

但干净副本实际是：

```
…発表しました。 また、関連する手法の…
            ↑ 多余的半角空格
```

**「diff 只出现标记行」这条检查放过了标记两侧的残留空白。** → 记为发现 F3。

### 第二次：连同两侧空白剥离，**当时判为通过，事后证明规则本身仍是错的**

> **后续修正（复核指出）**：这条规则会改写正文。
> `Graph <!-- claims: C-01 --> Transformer` → `GraphTransformer`，英文术语被粘连。
> 而且当时的第③步验证"按同一规则再剥离一次做比较"是**自洽检查**——两边用同一条错规则必然一致，**照样通过**。
> 规则已改为：标记默认独占一行（整行删除）；行内标记按 ASCII／日文邻接判断空格；验证换成三项不依赖剥离规则本身的检查。见 `fact-control.md` 3.5。
> **以下的"通过"只对当时那份测试稿成立**（该稿没有英文术语紧邻标记的情况），不构成规则正确性的证据。

```
$ sed -E 's/[[:space:]]*<!-- claims: C-[0-9]+ -->[[:space:]]*//g' script-7min.md > script-7min.clean.md
```

验证输出：

```
残留标记: 0
日文间多余半角空格: 0
行尾空白行: 0
工作稿剥离后 == 干净副本: True
干净副本本文字数: 1770（与工作稿一致）
```

判定：**通过**（修正剥离规则后）。
