# 研究叙事与想定问答

> **本文件中的全部例句、机构名、数字均为占位符**（`A手法`、`分野X`、`〇〇大学`），仅示范结构。**禁止把示例内容写入产出。**

前置：`fact-control.md` 的台账与「评审者判断模型」已完成。
产出日语文本前先读 `japanese-expression.md`。

## 1. 叙事的判定标准

叙事不是成果罗列，而是一条能让评委在听完后**自己得出"这个人该被资助"结论**的线。判定标准只有一条：

> 去掉任何一段，后面的段落还成立吗？成立说明那段是装饰，删掉。

## 2. 骨架（六段）

```
既有能力（我能做什么，有证据）
→ 问题（来源要能说清，见下）
→ 为什么这个课题是必要的（不做会怎样）
→ 方法如何解决（一层深度，细节留给质疑）
→ 学位／资助期间的 N 年如何验证（可执行、有里程碑、有失败预案）
→ 学术与社会的意义（对谁有用）
```

**问题的来源不必是"自己撞上的"。** 文献缺口、实践中遇到的障碍、导师课题的延伸、社会需求，都是正当来源。评委真正在听的是你能否回答**"你为什么关心这个问题"**——来源本身不加分也不扣分，说不清才扣分。

**N 由募集要项的资助期间与课程标准年限决定，不要默认三年**（见 `fact-control.md` 第 2 节）。

### 学科分支

| | 理工・医药 | 人文社科 |
|---|---|---|
| 第 4 段"方法" | 方法 → 数据 → 验证方式 → 评价指标 | 资料・史料・调查对象 → 分析框架・理论 → 论证方式 |
| 评委问"方法"时期待听到 | 可复现的步骤与可比较的指标 | 资料如何取得与处理、用什么理论视角、如何避免主观 |
| 第 5 段"验证" | 实验设计、比较对象、消融 | 阶段性的资料收集与写作计划、如何检验解释的妥当性 |

**把理工模板硬套到人文社科上，会产出评委看不懂的东西**，反之亦然。医药另需准备伦理审查与数据来源合规性。

> **`--full` 时**：骨架写完后停下，与「评审者判断模型」一起交给用户确认，得到答复再做第 4 节的问答。
> **局部模式（`--qa` / `--script` / `--mock`）时**：不要用骨架挡住产出。骨架缺失就从事实表推定一条、标明"为推定"，照常往下做（见 SKILL.md）。

## 3. 四个高频叙事难点

**转过研究方向，怎么说才不显得摇摆**
不要按"兴趣变化"叙述，按**能力积累**叙述：抽出前后经历共通的能力，指向现在的课题。
`分野Yでは〜という力を身につけました。その力は、いま取り組んでいる〜にそのまま必要になります。`

**工程实现经验不是科研结论**
定位成"把构想变成能跑的东西的实装力"，**不说成已验证的研究成果**。必须挂 claim ID，措辞落在允许含义内。

**面向非专业评委**
第 2 段（问题）用日常语言讲清"谁在为什么困扰"，第 4 段才出现方法名。技术深度留给 L3 追问。

**主动交代局限与风险**
这一项提升可信度的效果，通常大于多讲一个成果。三件套：
```
最大的风险是什么 → 怎么察觉它发生了 → 察觉后改做什么
```

## 4. 想定问答：五级体系

每一题都要标注**"评委在测什么"**——不知道在测什么，就无法判断答案够不够。

| 层级 | 典型问题 | 评委在测 |
|---|---|---|
| **L1 基础确认** | 自我介绍、研究动机、为何来日本／这所学校／这个研究室、毕业后打算 | 是否想清楚了；是否与本奖学金的目的一致 |
| **L2 学术解释** | 研究问题是什么、方法、创新点在哪、数据从哪来、怎么评价、局限是什么 | 能否用自己的话说清；深度是真的还是背的 |
| **L3 技术追问** | 这真的做得完吗、和什么比、失败了怎么办、数据拿不到怎么办、时间怎么分配 | 计划是可执行的还是纸面的 |
| **L4 可信度压力** | 论文现在什么状态、你个人具体做了什么、那个项目实际到哪一步了、进展如何 | 诚实度；与申请书和台账是否一致 |
| **L5 资助判断** | 为什么需要这笔资助、时间怎么用、能按期修了吗、之后怎么办 | 这笔钱投下去的回报与风险 |

L1・L5 面向全体评委；L2・L3 主要来自本专业评委；**L4 可能来自任何人，且最难临场应付**——它必须靠台账，不能靠机智。

### 准备量的换算

由画像里的**质疑时长**推算，不要凭感觉定题数：

```
现场实际被问到的题数 ≈ 质疑时长 ÷ 1.5 分（一问一答含追问）
应准备的题数 ≈ 实际题数 × 2〜3
```

例：质疑 10 分钟 → 现场约 6〜7 题 → **准备 15〜20 题**。

倍数是因为问哪几题不可控。层级分配参考 L1:L2:L3:L4:L5 ≈ 3:4:4:5:3，**这是未经验证的经验起点，不必精确套用**——按评委构成调整：非专业评委多则 L1・L5 加重，本专业评委多则 L2・L3 加重。

**但 L4 的题数取 `max(比例分配, 未到终点的主张数)`。** 未到终点的主张多于比例分配时，以主张数为准并相应扩大总量——L4 的覆盖是强制的（见第 6 节），比例只是起点。

## 5. 每题的记录模板

写入 `./interview-prep/qa.md`，字段见 `assets/qa-ledger-template.md`：

```
問い：
評委在测：
短答（30秒以内・まず結論）：
展開（60〜90秒・聞かれたら）：
キーワード（これだけ覚える）：
想定される追問：
claim ID：（該当しない場合は「なし」）
越えてはいけない線：
```

- **claim ID 不是每题必填。** 涉及履历・成果・状态・研究结果的题必须填；动机、价值判断、将来意愿、一般性解释类的题填 `なし` 即可。
- **短答先给结论**，再给理由。日语面试里先铺垫会让评委不知道你要说什么。
- **キーワード 是给紧张时用的**：忘了整段也能靠 3〜5 个词把话说回来。
- **「越えてはいけない線」写死**：这题最容易说过头的地方是哪句、该停在哪。

## 6. 覆盖度检查

出完问答后逐条确认：

- [ ] L1 全部覆盖（含"为什么是这所学校／这个研究室"这类必问项）
- [ ] L2 覆盖研究计划的每个主要组成部分
- [ ] L3 至少覆盖：可行性、比较对象、失败预案、数据获取、时间分配
- [ ] **L4 覆盖台账里每一条"状态尚未到终点"的主张**（审稿中的论文、未公开的项目、未正式化的合作、已变更的资助状态）
- [ ] L5 至少 3 题
- [ ] 每题都标了"评委在测什么"
- [ ] **标了 claim ID 的题**，其 ID 存在于台账中（标 `なし` 的题不检查）
