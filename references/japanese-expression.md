# 日语表达规范（横切：产出任何日语面试用文本前先读）

> **本文件中的全部例句均为句式样板**，其中的研究内容、机构名、数字为占位符（`A手法`、`分野X`、`〇〇大学`）。**禁止把示例内容写入产出。**

适用对象：发表原稿、想定问答、模拟回答、幻灯片文案。

## 0. 哪些是语言无关的，哪些是日语特有的

**"英语场次不覆盖表达规范"指的是日语特有的那部分，不是整个表达层。** 一刀切会把下面左栏也丢掉，而它们在任何语言的面试里都成立。

| **语言无关（英语场次同样适用）** | **日语特有（英语场次不适用）** |
|---|---|
| 三档能力分级（A／B／C）的思路 | です・ます体统一 |
| 一句一信息 | 二重敬語、`〜させていただきます` 的滥用 |
| 术语首次出现时给一句日常语解释 | 论文腔（`〜における` `〜に関する` 连用） |
| 面向非专业评委：先说困扰、后出方法名 | 第 5 节的固定句（日语原文） |
| 数字与状态词只说台账里有来源的 | 第 6 节的注音・转写 |
| 不过度谦逊、不过度断言 | 幻灯片的体言止め |
| 答不上来时的**三段框架**（承认边界→怎么查证→拉回邻近） | 那三段的具体日语句子 |

**英语场次的做法**：右栏整体跳过；左栏照常执行，但**句子要本人或熟悉英语面试的人来定**——本 skill 不提供英语的例句、词表与语速基准。

## 1. 按「口头运用能力自评」分三档

分档来自画像，**不使用 JLPT 等级**——JLPT 不测口语。

| 档 | 写法 | 原稿定位 |
|---|---|---|
| **A 能自如问答** | 可用复文与专业术语，可即兴展开 | 原稿是骨架，不逐字背 |
| **B 能应对预想问题** | 一句一信息；连体修饰不超过一层；追问的答案预先铺好 | 原稿逐字准备，但要写成能自然说出口的样子 |
| **C 基本靠背诵** | 一句 20〜30 字以内；主语与谓语靠近；术语先给日常语解释 | 全稿可背诵，另备「听不懂时」的固定句 |

拿不准时按低一档写。**降档写的稿子高档的人也能说，反过来不行。**

## 2. 通用规则

- **です・ます体统一——这条只管口述稿**（发表原稿、问答的短答与展开、模拟回答）。
  **幻灯片的标题、图注、表头不受此限**：体言止め（`〜の比較`）、名词短语、简短的である体都是正常的学术幻灯片写法，硬写成 です・ます 反而不自然。页面上的**完整句子**仍按 です・ます。
- **一句一信息。** 一个句子只承担一个信息点，说完一个再说下一个。
- **避免二重敬語**：`おっしゃられる` → `おっしゃる`；`拝見させていただきました` → `拝見しました`。
- **避免 `〜させていただきます` 的滥用**。能用 `〜します` `〜したいと考えています` 的地方就用。
- **避免论文腔**：`〜における` `〜に関する` 连用、名词化堆叠，读起来生硬、也背不下来。拆成动词句。
  - `A手法における精度向上に関する検討` → `A手法の精度をどう上げるかを検討しています`
- **不过度谦逊**：`まだまだ未熟ですが` 连发会削弱可信度，全稿最多一次。
- **不过度断言**：避免 `必ず` `間違いなく` `完全に`。用 `〜と考えています` `〜を目指しています`。

## 3. 术语的处理

首次出现时给一句日常语解释，之后可直接使用：

```
A手法、つまり〜を〜する方法を用いています。
```

面向非专业评委时，**先说要解决的困扰，再说方法名**——顺序反了对方就跟丢了。

```
（悪い順序）A手法を用いて分野Xの課題に取り組んでいます。
（良い順序）分野Xでは〜という困りごとがあります。それに対してA手法という方法を使っています。
```

## 4. 数字与状态词

- **数字只说主张台账里有来源的**。凭印象的数字一律不说，改成定性表述。
- **状态词按台账条目的「允许含义」选**。危险词的判断见 `fact-control.md` 第 3.3 节，本文件不重复列表。
- 改写后必须仍落在该条目的允许含义内——这是唯一判定标准，不存在通用替换句。

## 5. 答不上来时的固定句（**必须练到条件反射**）

这几句的实用价值高于任何一个准备好的答案。

| 场景 | 句子 |
|---|---|
| 没听清 | `申し訳ありません、もう一度お願いできますか。` |
| 确认理解 | `〜という意味でよろしいでしょうか。` |
| 需要一点时间 | `少し考えるお時間をいただいてもよろしいでしょうか。` |
| 部分能答 | `〜の点についてはお答えできます。〜の点は現時点では十分に検討できていません。` |

**超纲问题的止损：三句收住，不硬编。**

```
1) 承认边界：その点は現時点で十分に検討できていません。
2) 怎么查证：〜を調べた上で判断したいと考えています。
3) 拉回邻近能讲的：関連して、〜については〜と考えております。
```

**绝对不要编造。** 面试官追问的目的多数是探边界，坦率承认的扣分远小于被拆穿。

## 6. 注音（ruby）形态

按画像的「注音需求」执行：

**先分清两件不同的事**，混在一起是这一项最容易出的错：

| | 决定什么 | 由哪个画像项决定 |
|---|---|---|
| **表达难度** | 句子多长、用不用复文、术语要不要解释 | 口头运用能力（A／B／C 档） |
| **文字表记形态** | 汉字／假名／罗马字怎么写 | 注音需求 |

**降低汉字密度 ≠ 全假名。** 两者是不同的操作，不能互相替代。

| 需求 | 做法 | 交付物 |
|---|---|---|
| 不需要 | 不加 | 汉字假名混写稿 |
| 重点词 | 专有名词、数字读法、音训易错词加 ruby | 混写稿 ＋ 部分 ruby |
| 全文 ruby | 全部汉字加 ruby，**正文汉字保持不变** | 混写稿 ＋ 全 ruby |
| **全假名** | **把正文实际转写成假名**（`資料` → `しりょう`）。只是少用汉字**不算完成** | 全假名稿 |
| **罗马字** | **把正文实际转写成罗马字** | 罗马字稿 |

全假名／罗马字稿对日语母语者难读，但它的用途是**本人朗读与背诵**，不给评委看，所以这是正常的。
同时按 C 档缩短句子会更好读，但**缩短句子不能代替转写**。

### 转写时实际会撞到的三类问题

**① 同一汉字在不同活用形下读音不同**

```
出しました → だしました      出て いません → でて いません
```

同一个「出」，一处 だ 一处 で。**不能做词典式的整词替换**，要逐处按活用判断。

**② 同音异义——专业术语尤其危险**

```
しりょう ＝ 資料 ／ 史料 ／ 飼料
ぶんしょ ＝ 文書 ／ 分署
きかん   ＝ 期間 ／ 機関 ／ 器官
```

在人文社科里，`資料` 与 `史料` 是两个不同概念。转成假名后，**本人复习时无法从假名稿反推自己当初写的是哪一个**。

**③ 分かち書き是功能性空白**

给学习者用的分词空格不能省，和 claim 标记剥离那轮踩过的是同一个坑（见 `fact-control.md` 3.5）。

### 因此：全假名／罗马字稿**必须成对交付**

| 稿 | 用途 |
|---|---|
| 汉字假名混写稿 | **确认语义**。同音异义只能在这一份上分辨 |
| 全假名／罗马字稿 | **朗读与背诵** |

只给转写稿等于让本人拿着一份自己读得出、却读不懂的材料。
**转写完成后，专有名词与音训易错词逐个向本人确认读音**——这是出错率最高的地方。

无论自理还是委派外部技能，**专有名词的读音必须抽查**（人名、机关名、学会名、专业术语），这是注音出错率最高的地方。

## 7. 产出前检查清单

- [ ] 口述稿全文 です・ます体，无である体混入（幻灯片标题・图注不适用此条）
- [ ] 无二重敬語、无 `〜させていただきます` 滥用
- [ ] 每句只承担一个信息点，长度符合所在档次
- [ ] 术语首次出现处有一句解释
- [ ] 面向非专业评委处，先说困扰再说方法名
- [ ] 所有数字与状态词可追溯到台账条目，且落在允许含义内
- [ ] `まだまだ未熟ですが` 类谦辞全稿不超过一次
- [ ] 无 `必ず` `完全に` 等断言词
- [ ] 答不上来时的固定句已单独整理成一页，供本人反复练
- [ ] 注音形态符合画像；专名读音已抽查
