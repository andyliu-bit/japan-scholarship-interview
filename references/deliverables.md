# 成果物：发表原稿与幻灯片

> **本文件中的时间分配、页数、字号均为起点值**，按实际场次调整。例句中的内容为占位符，**禁止带入产出**。

前置：台账与叙事已完成。产出日语文本前先读 `japanese-expression.md`。

**纯质疑（无发表）的场次跳过本文件的全部内容**——没有发表就没有原稿，**不要产出时长预算、字数预算与页面规格**。此时的"成果物"是想定问答的短答稿（暗記用），归 `narrative-and-qa.md` 管。
注音需求为全假名／罗马字时，降低汉字密度的对象也是这份短答稿。

## 1. 时长：三级制

**字数只是预警信号，真实朗读才是证据。**

| 级 | 做法 | 用途 |
|---|---|---|
| **① 初稿估算** | 约 280〜320 **日文字符**／分（含标点。带 ruby 的稿按原文字数计）。**这是日语的基准，英语等其他语言不适用**——换语言就要另找基准，本 skill 不提供 | 只用于分配预算，**不作为通过标准** |
| **② 分段预算** | 给每一段分配秒数，合计留 10% 缓冲 | 写稿时的结构约束 |
| **③ 最终验收** | **本人至少两次真实朗读，取较慢的一次为准** | 唯一的通过标准 |

**目标是规定时长的 88〜93%，不是写满。** 7 分钟的场次目标 6:10〜6:30。紧张时语速会变化，评委也可能中途插话。

朗读实测**超时**的处理顺序：**删内容 → 合并段落 → 最后才考虑加快语速**。靠加速换来的时间会在现场丢掉。

朗读实测**不足**（初稿高发，别忽略——7 分钟的场次讲 5 分钟，等于主动放弃三分之一的陈述机会）的补充顺序：

**验证的具体性（指标・比较对象・判定基准）→ 意义与受益者 → 问题的现场感（谁在为什么为难）**

**不要补技术细节。** 技术细节属于 L3 追问，补进发表稿会同时触发"超时"和"非专业评委听不懂"两个失败模式。

**字数预算只在第一次朗读之前有效。** 280〜320 字/分是通用区间，对同一份稿会给出约 ±13% 的时长差（实例：1770 字 → 5:31〜6:19，横跨目标区间内外）。**第一次朗读实测后，用本人的实测速率反算字数预算**，之后按个人速率调整，不再用通用区间。

## 2. 原稿结构（以 7 分钟为例，按比例缩放）

| 段 | 内容 | 秒数 |
|---|---|---|
| 冒头 | 自我介绍 + 主题一句话 | 0:30 |
| 背景与问题 | 谁在为什么困扰（日常语言） | 1:10 |
| 为什么现在必须做 | 不做会怎样 | 0:50 |
| 方法 | 一层深度，细节留给质疑 | 1:40 |
| 验证与 N 年计划 | 里程碑 + 失败预案（N 由资助期间与课程年限决定） | 1:30 |
| 意义与结语 | 对谁有用 | 0:40 |
| 缓冲 | — | 0:40 |

合计约 6:20。**课外经历、兼职、个人开发的篇幅按与研究的相关性分配**，不设全局固定比例；与研究无关联的经历，在发表稿中通常一句带过或不出现，留给 L1 问答。

## 3. 幻灯片最小规格

**核心规则：每页服务一个口头结论，且页面内容不得与口述逐字重复。**

这不等于"留白"——图表、数据、流程图的密度高是合理的，学术发表本来就靠图说话。要避免的是**评委在读你正在念的同一句话**，那会让他既没听进去也没读进去。

**"逐字重复"的判定阈值＝句子级。**

| | 判定 |
|---|---|
| 页面出现口述稿中的**完整句子**（句点分隔的单位） | **禁止** |
| 关键词、专业术语、主语短语的重复（如页面写「〜が少ない地域ほど」，口述展开成完整句） | **正常且有益**——它帮评委把眼睛看到的和耳朵听到的对上 |

按"页面与口述不得有 N 字以上重叠"这种字符级规则去执行会**反向伤害**：页面会被逼着避开关键术语，评委反而对不上。判定只看有没有整句照搬。

- 每页顶部写该页的**结论**（一句话），不写"背景""方法"这种栏目名
- 一页以一图或一表为主；文字块每页不超过 5 行
- 字号下限保守取：标题 28pt 以上，正文 18pt 以上
- 术语在页面首次出现处给短注
- **claim ID 写进演讲者备注**，或单独维护 slide-claim 对照表
- **最终对外版本剥离全部 claim 标记**——剥离必须在两遍核验之后，顺序见 `fact-control.md` 3.5

页数起点：发表分钟数 ÷ 1 分钟前后（7 分钟 ≈ 6〜8 页），加封面与结语。

## 5. 委派契约

### 先判断环境里有没有可委派的对象

**按功能判断，不按名字判断**：查看当前环境可用的技能／工具清单，看有没有描述覆盖「幻灯片・演示文稿・slides 的生成」或「假名注音・ruby・ふりがな」的条目。

- 名字不匹配但功能覆盖 → **可以委派**
- 有多个候选 → 选描述最贴近本用途的一个，并告诉用户选了哪个、为什么
- 一个都没有 → 走第 6 节的降级路径
- **不假定任何特定技能存在**，也不因为找不到某个熟悉的名字就判定"没有"

### 幻灯片生成・渲染检查

**交付给对方的输入**：每页的口头结论、页面要素清单（图／表／文字块）、语言、字号下限、claim 映射、页数上限。
**验收条件**：
- [ ] 能实际渲染出图并逐页确认
- [ ] 页面内容不与口述逐字重复
- [ ] 危险词的**命中项全部经过审阅**，每一处都有允许该含义的台账条目支持（**不是"零命中"**）
- [ ] 占位符（`〇〇`、`【】`、`TODO`）全部替换完毕

### 假名注音（ruby）

**交付给对方的输入**：**已确认定稿**的日语原稿（未定稿不送）、注音形态（见画像）。
**验收条件**：
- [ ] 专有名词读音已抽查（人名・机关名・学会名・术语）
- [ ] 注音未破坏原文
- [ ] 按目标形态输出（重点词／全文 ruby／全假名／罗马字）

### 验收不通过时

1. **带着具体的不合格项退回重做**，不要自己动手改对方的产物——改了之后双方的版本会分叉
2. 同一项连续两次不通过 → **停止委派，转第 6 节的降级路径**，并把已经发生的偏差告诉用户
3. 无论退回还是降级，**都不得把未通过验收的产物当作完成品交付**

## 6. 无专用技能时的降级

**自理产出的是「页面设计稿」，不是可放映的文件。** 交付时必须说清这一点——用户以为拿到的是能直接用的幻灯片，是这条路径最容易造成的误解。

设计稿至少包含：原稿与页面的对应表、每页的口头结论、每页的文字块全文、页面要素（图／表）的说明、claim 映射。

- **幻灯片**：按第 3 节的最小规格自行生成。
- **无渲染手段时**：降级为逐页文字自查清单（对照第 3 节逐条打勾），并**明确告知用户"未做渲染确认"**。
- **注音**：按 `japanese-expression.md` 第 6 节自理，专名读音仍必须抽查。

**底线：未确认渲染、未确认读音正确，不得宣称完成。**
