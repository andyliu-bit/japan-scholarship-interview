# 事实控制：画像 · 信息收集 · 主张台账 · 评审视点

> **本文件中的全部例句、机构名、数字均为占位符**（`A手法`、`分野X`、`〇〇大学`、`N件`），仅示范句式与结构。**禁止把示例内容写入任何产出。**

## 1. 画像判定

5 项见 SKILL.md。此处补充每项分支后的实际差异：

| 项 | 分支后的差异 |
|---|---|
| **研究领域** | 理工：问题→方法→验证→指标，可行性是重点。人文社科：问题意识→先行研究中的位置→资料与分析方法→意义；"方法"常指资料处理与理论框架，硬套理工模板会产出评委看不懂的东西。医药：伦理审查、数据来源合规性会被追问 |
| **口头运用能力** | 能自如问答：可用复文、可即兴展开。能应对预想问题：一句一信息，追问要预先铺好答案。基本靠背诵：全稿短句化，术语先给日常语解释，并额外准备"听不懂时"的固定句 |
| **注音需求** | 决定原稿的交付形态。需要全假名或罗马字时，**原稿本身**就要降低汉字密度，而不是事后加注音 |
| **形式与时长** | 纯质疑场次跳过幻灯片工序。线上场次必须做设备与断线预案。发表 N 分钟决定字数预算 |
| **参加条件** | 海外远程：时差换算、当地时间确认、材料寄送截止。在日：交通与到场时间 |

JLPT 等级、母语、在留状态记入 factsheet 作为背景信息，**不作为分支条件**。

## 2. 信息收集

写入 `./interview-prep/factsheet.md` 与 `program-brief.md`（写盘前先做 SKILL.md 的泄漏防护检查）。

| 类别 | 必需字段 | 缺失时 |
|---|---|---|
| **申请人** | 学历与在学状态、修了预定时期、专业、指导教员、研究经历、业绩、项目、课外活动、毕业后规划 | 标 `【要確認】`，不推测 |
| **研究** | 问题、为什么现在必须做、方法、数据来源、验证方式与指标、创新点、局限与风险、**学位／资助期间的 N 年计划** | 局限与风险最常被漏，**必须主动问**——评审很看这一项 |
| **奖学金** | 资助目的、金额与期间、评审形式（发表有无／时长／人数／语言）、评委构成、提交物、截止日 | 查不到就列成"需向主办方确认"清单 |
| **证据** | 每条主张的来源与状态（见第 3 节） | 无来源的主张不进台账，也不得写入产出 |

### 来源优先级（**按事实类型判断，不存在跨类型的固定排序**）

| 事实类型 | 优先来源 |
|---|---|
| 奖学金规则、截止日、评审要求、提交物 | 当前有效的官方资料（募集要项・選考要領・通知） |
| 申请时填写了什么 | 已提交的申请书本身 |
| 现在的状态（论文・资助・在学・就职・项目） | 最新的一手记录，或申请人的当前确认 |
| **计划的年限**（几年计划） | 募集要项的资助期间 ＋ 该课程的标准年限。**不要默认三年**——修士通常 2 年，博士后期多为 3 年，制度与国家不同则另计 |
| 动机、意愿、将来规划、价值判断 | 申请人本人的陈述 |
| 研究内容、方法、结果 | 申请人的原始记录（代码・数据・投稿稿），其次为本人说明 |

### 申请提交后发生的状态变化

论文、资助、就职、在学、项目的状态，都可能在提交申请书之后发生变化。**不要让旧申请书压过新事实，也不要单方面改写申请书的记载。** 登记为三段式：

```text
提交时的状态：（申请书上写了什么）
当前的状态：（截至 YYYY-MM-DD 的事实）
面试时的说明：（一句话，诚实、简短、不辩解）
```

被问到时按这三段回答；不被问到时不主动展开。

**例外：官方要求主动申告的情形，按官方要求办，不适用"不问不说"。** 典型的是**资格・併給・收入・在学状态的变更**——募集要项或采用通知里常写有"变更时须申告"的条款。

→ 先按 3.1.1 回查条款：**有申告义务的，走申告程序（不是等面试时被问）**；条款不明的，列入"需向主办方确认"。
**"不问不说"只适用于没有申告义务的事实。** 把有义务申告的事压着不报，性质不是"不主动展开"，是隐瞒。

## 3. 主张台账

写入 `./interview-prep/claims.md`。**登记范围见 SKILL.md 的四类**，不必逐句登记。

### 3.1 格式

```text
[C-03]
主张：分野X における査読付き学術誌論文
状态：修正稿を再投稿、現在査読中（YYYY-MM-DD 時点）
允许含义：投稿中 / 修正稿を再投稿済み / 査読中
危险表述：採択 / 掲載済み / 発表済み
来源：投稿システムの記録（本人確認 YYYY-MM-DD）
复核期限：YYYY-MM-DD（面试日前）
```

`状态` 必须带**时点**，并设复核期限。面试日与登记日之间状态可能变化，临考前重新确认一次。

### 3.1.1 影响资格的主张必须回查官方材料

登记范围第 ④ 类（影响申请资格或评审判断的事实）**光登记不够，要去募集要项找对应条款核对**，把结果写回 `program-brief.md`：

| 这类主张 | 要回查的条款 |
|---|---|
| 其他奖学金的申请・受给 | 併給の可否、金额上限 |
| 在学・休学・留年的状态 | 申请资格的在学要件 |
| 就职・兼职・收入 | 收入制限、就労制限 |
| 国籍・在留资格 | 应募资格 |
| 既往的受给歴 | 重複受給の制限 |

**官方材料里查不到的，列入"需向主办方确认"，不要自行判断合规。** 资格问题被问到时答错，代价远大于研究内容答得不够深。

**"回查"指读官方原文。** 看自己或他人整理的摘要、清单、笔记**不算回查**——那是二手转述，可能已经漏掉或改写了条件。记录核查结果时区分三级：**文件存在／读了部分正文（记页码）／核对过具体条款**。

### 3.2 状态记法：只有论文近似单线，其余用多维矩阵

**学术论文（近似阶梯）**
构想中 → 执笔中 → 投稿准备中 → **投稿済み（編集部確認中・査読前）** → 査読中 → 修正要求（major/minor）→ 修正稿再投稿・査読中 → 採択 → 掲載済み

**投稿しただけでは `査読中` とは限らない。** 送到审稿人手上之前有编辑部确认阶段（desk reject 也发生在这里）。投稿系统的状态显示什么就写什么，不要从"已投稿"直接推断"审稿中"。

**学会发表（三轴独立）**
```
审查状态：投稿中／採択／不採択
实施状态：発表前（日程確定含む）／発表済み／取消
记录形态：なし／予稿集収録／論文集収録／DOI 付与
```
仅被收进预稿集而未实际登台，不能说 `発表しました`。

**软件・系统・项目（四轴独立）**
```
开发成熟度：構想／プロトタイプ／テスト中／RC／安定版
开放范围：非公開／限定テスト／一般公開／ストア掲載
使用证据：なし／内部テスター／実ユーザー／検証可能な規模
商业状态：なし／試験課金／収入あり／継続収入
```
四轴不构成先后关系：可能先有真实用户后一般公开，也可能有收入而未上架。**每轴各自说清，不用一个词概括。**

**共同研究・企业合作（四轴独立）**
```
关系性质：面談・意見交換／継続的な議論／助言・指導／実際の共同作業
正式度：なし／口頭合意／書面契約
活动实态：なし／不定期／定期・継続
共同成果：なし／内部資料／共同発表・共同出願
```
无书面契约也可能有实质共同作业，反之亦然。仅有一次交流不能说 `共同研究しています`。

**资助・奖项（两轴）**
```
审查状态：申請中／一次通過／採用／不採用
受给状态：受給前／受給中／受給終了／辞退
```

### 3.3 危险表述（按类别判断，不追求穷举词表）

> **五个分类是语言无关的，下面的词表是日语的。** 换成其他面试语言时，分类照用，词表要另建——本 skill 不提供。

**扫描时的常见假阳性**（实测确认过的五种，逐条确认即可，不要改）：

| 形态 | 例 |
|---|---|
| 学科・领域名的一部分 | `臨床医学のEBM`（不是在说自己做临床） |
| 指本奖学金本身 | `ご採択いただければ`（不是论文採択） |
| 将来的意愿 | `共同研究を積み上げたい`（不是已有共同研究） |
| 第三方的事例 | `〇〇社と〇〇社の共同研究事例`（不是自己的） |
| 表格・模板自带的说明文 | 申请书里的`共同研究の場合は担当部分を明記` |

| 类别 | 典型词 |
|---|---|
| 状态升格 | `発表済み` `掲載` `採択` `受理` `特許取得` `リリース済み` |
| 外部认可 | `評価された` `高く評価` `認められた` `推薦された` |
| 合作关系 | `共同研究` `連携` `提携` `共同開発` `産学連携` |
| 部署・使用 | `実用化` `導入実績` `臨床` `ユーザー数` `商用化` `運用中` |
| 性能最高级 | `世界初` `初めて` `最先端` `最も優れた` `SOTA` `大幅に上回る` |

**改写不给固定替换句。** 同一个词在不同语境下的正确改写不同——`SOTA` 出现在"今后想验证的计划"里，与出现在"已完成的比较实验"里，改法完全不同。判断标准只有一条：**改写后的表述必须落在该主张台账条目的「允许含义」之内。**

**验收条件不是"零命中"。** 台账支持时，危险词本身是正当的（已掲載の論文について `掲載` と言うのは正しい）。正确的验收条件是：**命中项全部经过审阅，且每一处都有允许该含义的台账条目支持。** 把目标定成"一个危险词都不出现"，会逼出把真实成果说小的另一种失真。

### 3.4 贡献度：两个独立维度，不要压成一档

```
著者身份（论文・发表）：筆頭著者／共著者／謝辞のみ／著者ではない
担当范围（研究・开发）：構想／設計／実装／評価／執筆 のうちどれを担当したか
```

**两者不可互换。** 项目里做了很多但不是著者，就只说担当范围，不暗示著者身份；是共著但只负责一部分，就说清是哪一部分。
团队成果不说 `私が開発しました`，说 `プロジェクトの中で、私は〜を担当しました`。

### 3.5 下游标记与剥离

### 标记的写法：**默认独占一行**

```markdown
<!-- claims: C-03 -->
この段落の本文がここに続きます。
```

标记单独成行，紧贴它所修饰的段落。剥离＝**整行删除**，不触碰正文任何字符——这样能从根本上避免下面那类事故。

幻灯片：写入演讲者备注，或单独维护 slide-claim 对照表。

### 不要写行内标记

- **新稿一律用独占行。**
- **表格单元格不放标记**，改用外部映射表（`| 行/页 | claim ID |`）。
- 已有稿里的遗留行内标记按下面处理，**不要新增**。

### 遗留行内标记：剥离只删注释，**不碰空白**

**剥离不负责猜排版。** 机械步骤只做一件事：

> 删除标记子串本身。**任何空白原样保留。**

产生的连续空格**不自动处理**，逐处列入「空白调整清单」，**每处单独决定、单独复核**：

| 位置 | 前后文 | 决定 |
|---|---|---|
| L12:5 | `Graph  Transformer` | 合并为 1 个（英文术语间） |
| L20:4 | `しりょう  を よみます` | 保留 1 个（分かち書き，学习稿刻意的分词） |

**清单之外不得有任何空白改动。**

### 为什么不按字符类型判断

试过两版规则，都会改写正文（实测见 `tests/runs/2026-09-17-strip-rule.md`）：

| 输入 | 期望 | 「两侧空白全删」 | 「按字符类型加空格」 |
|---|---|---|---|
| `GPT<!-- C-01 -->4` | `GPT4` | `GPT4` ✓ | `GPT 4` ✗ |
| `Graph <!-- C-01 --> Transformer` | `Graph Transformer` | `GraphTransformer` ✗ | `Graph Transformer` ✓ |
| `しりょう <!-- C-01 --> を よみます` | `しりょう を よみます` | `しりょうを よみます` ✗ | `しりょうを よみます` ✗ |

**正确的空白取决于原稿本来有什么、以及那份稿子的用途**（学习稿的分かち書き要保留，正式稿不要），**不取决于字符是 ASCII 还是日文**。字符类型只是相关性，不是因果。所以不让机械步骤去猜。

**剥离与核验的顺序固定，不可颠倒**——标记一旦剥离，就再也无法靠 ID 核验成品：

1. 在**带标记的工作稿**上完成两遍核验（机械 ＋ 语义）
2. **机械剥离**：删除仅含标记的整行；删除行内标记子串。**不动任何空白。**
3. **不变式检查**：除被删的标记（及仅含标记的整行）外，**没有任何字符被增删，空白也算字符**。
   **必须用独立于剥离实现的方式核对**——逐字符比对，或用手写预期输出的固定用例先验证剥离实现本身。
   **用同一个剥离实现去生成对照，等于什么都没验**（两边一致是必然的）。
4. **空白调整**（只在有连续空格时）：逐处列入清单、逐处决定、逐处复核。改完后，两稿的差异**必须只出现在清单列出的位置**。
5. 在干净副本上检查占位符与排版，此后不再改正文

> **不要用"把工作稿按同一规则再剥离一次，看是否与干净副本一致"来验证。** 那是**自洽检查**：规则本身错了，两边会一起错，检查照样通过。
> 同理，"diff 只出现标记行"也不足以证明正确。
>
> **剥离实现本身只能靠手写预期输出的固定用例来验证**（见 `tests/runs/2026-09-17-strip-rule.md`）。
> 不变式是在剥离实现已被固定用例证明正确之后，用来检查**其他转换方式**（手工编辑、别的脚本、外部技能的产物）的。**两者的顺序不能颠倒。**

第 4 步之后若正文仍需修改，**回到第 1 步重走**，不要在干净副本上直接改。

### 3.5.1 未实装・未验证机构的"动作例"

讲解自己设计的机制时，常会举一个走查例（"例如候选 B 会从第 1 位降到第 3 位"）。

**规则：动作例必须在说出口的当下标明它自己的性质**——概念示意／仿真・原型实测／已验证结果——**涉及实测的要说清验证范围**。不能只在后面某一段补一句"尚未实装"。

**性质按这个例子自己的证据判断，不按整个系统的完成度判断。**

```
危险：たとえば、候補Bは〜3位に下がります。
      （……二段后）なお、この仕組みはまだ実装前です。
安全：図は動作のイメージです。実装後に、たとえば候補Bが〜3位に下がる、
      といった挙動を想定しています。
```

理由：**听的人是线性接收的。** 先听到一个用现在形陈述的结果，再听到"未实装"，前一句已经作为既成事实进入印象了。文字稿上前后文能互相修正，口头不能。

**判定按每一个例子自己的证据，不按整个系统的状态。** 系统整体未完成，不代表其中的局部原型、仿真、实验没有真实结果：

| 这个例子的来源 | 怎么说 |
|---|---|
| 纯概念示意（还没跑过） | 明确说是设想／动作イメージ |
| 仿真或原型实测 | 说清**跑的是什么环境、验证范围到哪**（"原型上、在 〇〇 条件下确认了〜"） |
| 已验证的结果 | 按证据正常陈述，**不要降格成"设想"** |

**把有实测的结果说成"设想"，和把设想说成结果一样是失真**，只是方向相反。逐个例子对照台账里对应条目的状态来判断。

### 3.5.2 关于第三方的主张（指导教员・研究室・合作方）

指导教员的业绩、研究室的网络、合作方的实力——**这些不是申请人的事实，不进登记范围**，但面试中会被同样地追问（"具体的にどの共同研究ですか"）。

处理方式：

- **单独列一张"第三方主张"表**，不混进主张台账
- 每条记：**申请人能证实到什么程度**（亲身参与／听说／公开可查）
- **答不出细节的，就不要主动说**——说了反而制造一个自己填不上的坑
- 公开可查的（论文数、编委职位、公开项目）可以说，但要能说出查证来源

| 第三方主张 | 申请人能证实的程度 | 面试中可说到哪 |
|---|---|---|
| 〇〇の国際的なネットワーク | 公开可查（编委・学会职位） | 可说，能举出依据 |
| 〇〇と企业的合作关系 | 只是听说，无细节 | **不主动提** |

**可自动检查**：文中出现的 `C-NN` 是否已登记、ID 是否失效、危险词是否命中、状态时点是否超过复核期限。

**无法自动检查、必须逐段人工或模型审阅**：
- 本该挂 ID 却没挂的段落（除非另行定义可判定的结构，工具无法可靠发现）
- 委婉改写导致的语义升格
- 暗示性上下文（把审稿中的论文与已发表论文并列陈述）
- 口头回答时的即兴越界

**因此核验必须两遍：先跑 ID 与词表检查，再逐段读上下文判断语义。不得宣称"已自动核验完毕"。**

## 4. 募集要项与评审视点分析

从**官方材料**抽取，写入 `program-brief.md`（附来源）。回答这 6 个问题：

1. 这笔资助真正想支持什么（募集要项的目的条款）？
2. 评委大概是什么构成——本专业／跨专业／非研究者／行政？
3. 面试形式：发表几分钟、质疑几分钟、几位评委、语言、线上线下？
4. 官方是否公布了评审标准或配分？公布了就直接照它组织内容。
5. 申请人最需要证明的三件事是什么？
6. 哪些内容应当弱化——与研究关联弱的经历、无法核实的成果？

### 类型分类（**提问用的初始假设，不是结论**）

| 类型 | 常见评委 | 可能的侧重 |
|---|---|---|
| 大学内部 | 本校教员，含跨专业 | 学术潜力、能否按期完成学位 |
| 民间财团 | 理事、企业相关者，多非研究者 | 人柄、来日理由、毕业后去向、通俗可懂 |
| 政府系 | 学术＋行政 | 形式合规、材料一致性 |

**用法**：拿这张表去对照官方材料**提问与验证**。官方写明的一律以官方为准；**没有官方依据时不得按此表下结论。**

输出一段简短的"评审者判断模型"（3–5 句），供后续叙事、问答、原稿全程引用。

## 5. `【要確認】` 规则

- 事实不足时保留 `【要確認】` 并继续推进其余部分，不因单点未确认而停摆。
- 每次交付都在末尾汇总当前未解决的 `【要確認】` 清单。
- **最终核验时必须全部关闭，或被明确保留**（本人知情并已准备应答）。带着未处理的 `【要確認】` 上场，等于把风险留在了口头回答里。
